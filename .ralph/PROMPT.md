# SmartFinances (Rich-Uncle-Scrooge) — Ralph Development Instructions

## О проекте

Telegram-бот «Дядя Скрудж» для учёта личных финансов с ИИ (OpenAI GPT) для понимания естественного языка на русском. Пользователь пишет обычным текстом или голосом — бот сам определяет intent, сумму, категорию и выполняет операцию после подтверждения кнопкой.

## Технологический стек

- **Python 3.10+**, python-telegram-bot 20.7
- **SQLAlchemy + SQLite** (ORM, файловая БД)
- **OpenAI API** (gpt-4o-mini → gpt-4o каскад)
- **Google Sheets API** (экспорт/импорт)
- **Pydantic** (валидация LLM-ответов)
- **SpeechFlow** (голосовые сообщения → текст)
- **yookassa** (платежи) — ДОБАВИТЬ
- **pytest** (тесты)
- **Docker + docker-compose** (деплой)

## Принципы разработки

1. **НЕ удалять существующий код** — весь текущий функционал (текстовый ввод, голосовой ввод, все команды) должен продолжать работать. Новый код добавляется рядом, не заменяя старый.
2. **Русский язык в UX** — весь пользовательский интерфейс на русском. Код и комментарии на английском.
3. **Подтверждение операций** — все мутации через PendingAction + inline-кнопки ✅/❌.
4. **Тесты обязательны** — каждая новая фича покрывается pytest тестами в `tests/`.
5. **Один файл = одна ответственность** — не раздувать файлы, выносить в новые модули.
6. **Кнопка «Главное меню»** — ВСЕГДА должна присутствовать во всех ответах бота, во всех вкладках и разделах. Пользователь должен мочь вернуться в главное меню из любого места.
7. **Обратная совместимость БД** — не ломать существующие таблицы. Новые поля — nullable. Если нужны миграции, использовать alembic.
8. **Запускать pytest после каждого изменения** — `pytest tests/ -v`
9. **Живая документация (ОБЯЗАТЕЛЬНО)** — после каждой реализованной фичи или значимого изменения ОБНОВЛЯТЬ документацию в `docs/ARCHITECTURE.md`. Это критически важно: документация — единственный способ для нового ИИ-ассистента (или разработчика) в новом диалоге понять что уже сделано, как всё работает и как не сломать существующий функционал.

## Требования к живой документации (`docs/ARCHITECTURE.md`)

Этот файл — «источник правды» о проекте. Он должен поддерживаться в актуальном состоянии ПО МЕРЕ РАЗРАБОТКИ, а не после. Каждый раз когда ты реализуешь задачу из fix_plan — обнови этот файл.

**Документ должен содержать и поддерживать в актуальном состоянии:**

1. **Текущее состояние проекта** — что реализовано, что нет, какая фаза в работе
2. **Архитектура и структура файлов** — полный список модулей с описанием что делает каждый файл, какие функции экспортирует, от чего зависит
3. **Модели данных** — все таблицы БД со всеми полями, типами, связями. Если поле добавлено — сразу обновить
4. **Потоки данных (flows)** — как обрабатывается сообщение пользователя, как работает подписка, как работает paywall, как работают дайджесты. Пошагово, с указанием какие функции вызываются
5. **Callback-форматы** — полный список всех callback_data строк (`fin:...`, `menu:...`, `sub:...`) с описанием что каждая делает
6. **Конфигурация** — переменные окружения, их назначение, обязательность
7. **Ограничения и важные нюансы** — что нельзя менять, какие есть хаки, какие файлы критичны
8. **Changelog** — в конце файла вести лог изменений: дата, что сделано, какие файлы затронуты

**Формат**: Markdown. Язык документации: русский (для удобства чтения). Код в примерах — на английском (как в проекте).

**Цель**: любой ИИ-ассистент (Claude, GPT, другой) открывая новый диалог должен мочь прочитать ТОЛЬКО `docs/ARCHITECTURE.md` и полностью понять:
- Что за проект и как он работает
- Что уже реализовано и что ещё нет
- Какие файлы за что отвечают
- Как добавлять новый функционал не ломая существующий
- Какие есть «минные поля» (хрупкие места, неочевидные зависимости)

**Главное меню** (ReplyKeyboardMarkup, persistent):

- 📊 Отчёты

- ❓ Помощь

**Подменю «Отчёты»**:

**Подменю «Настройки»**:

**Подменю «Помощь»**:

**Онбординг нового пользователя** (при /start если нет счетов):

3. Выбор валюты кнопками

### Фаза 2: Интеграция ЮKassa

Разовые платежи (не автоподписка) через ЮKassa Python SDK (`yookassa`).

**Тарифы**:
- Месячная подписка: 190 ₽
- Годовая подписка: 1900 ₽

**Модель**: пользователь каждый раз покупает заново (разовый платёж). Бот записывает дату окончания подписки. Через месяц/год подписка истекает, бот напоминает о продлении.

**Модель доступа**: ВЕСЬ функционал бота доступен ТОЛЬКО по подписке (Pro). Без подписки бот не работает — показывает экран с предложением оформить подписку или активировать пробный период.

**Пробный период (Trial)**:
- Каждый новый пользователь может ОДИН РАЗ активировать бесплатную пробную Pro-подписку на 14 дней
- Активация через кнопку в онбординге или в экране «Подписка»
- После истечения trial — бот перестаёт работать, показывает экран покупки
- Повторная активация trial невозможна (хранить флаг `trial_used` в User)
- Во время trial доступен ВЕСЬ функционал Pro без ограничений

**Что включает Pro (весь функционал бота)**:
- Запись доходов/расходов/переводов (текст, голос, кнопки)
- Управление счетами
- Отчёты за любой период
- LLM-аналитика ("почему много на кофе") — безлимит
- Еженедельные и ежемесячные автоматические саммари
- Бюджеты по категориям с уведомлениями
- Экспорт/импорт Google Sheets
- Стрики, ачивки, напоминания

**Без подписки (после окончания trial или если trial не активирован)**:
- Бот показывает только экран: «Для использования бота нужна подписка» + кнопки «Месяц — 190₽», «Год — 1900₽» и описание возможностей
- Никакой функционал НЕ доступен

**Middleware проверки подписки**:
- Перед КАЖДЫМ действием (кроме /start, покупки подписки и активации trial) проверять `is_pro(user_id)`
- Если подписка не активна → показать paywall с кнопками покупки
- Paywall должен быть красивым: описание фич + кнопки тарифов + «Попробовать 14 дней бесплатно» (если trial не использован)

**Реализация**:
1. Новая таблица `subscriptions` (user_id, plan, paid_at, expires_at, payment_id, status)
2. Добавить в модель User: `trial_used` (Boolean, default=False), `trial_activated_at` (DateTime, nullable)
3. Сервис `services/billing.py` — создание платежа ЮKassa, проверка статуса, проверка подписки, активация trial
4. Функция `activate_trial(user_id)` — создаёт Subscription с plan="trial", expires_at=+14 дней, ставит trial_used=True
5. Функция `is_pro(user_id)` — проверяет есть ли активная подписка (включая trial)
6. Middleware `check_subscription()` — вызывается перед КАЖДЫМ действием кроме /start, покупки и активации trial
7. Paywall — красивый экран с описанием возможностей + кнопки: «🎁 Попробовать 14 дней бесплатно» (если trial не использован), «Месяц — 190₽», «Год — 1900₽»
8. Webhook или polling для подтверждения платежа
9. В меню «Настройки» → «Подписка» — показать статус, дату окончания, кнопки покупки/продления
10. Добавить в `.env`: `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`
11. Добавить `yookassa` в requirements.txt

### Фаза 3: Retention-фишки

**Еженедельный дайджест** (воскресенье вечер или понедельник утро):
- Сколько потратил за неделю vs прошлая неделя
- Топ-3 категории расходов
- Позитивная мотивация: «Вы потратили на кофе на 500₽ меньше — так держать!»
- Если расходы выросли — мягкое предупреждение с конкретными категориями

**Ежемесячный дайджест** (1-е число):
- Итоги месяца vs прошлый месяц
- Категории где сэкономил / где перерасходовал
- Общее сальдо

**Бюджеты по категориям** (Pro):
- Пользователь ставит лимит: «бюджет на кофе 3000₽ в месяц»
- Бот уведомляет при 80% и 100% расхода бюджета
- В отчёте показывает прогресс по бюджетам

**Дополнительные retention-фишки**:
- Стрик записей: «Вы записываете расходы 7 дней подряд 🔥»
- Напоминание если не записывал 3+ дня: «Давно не видел записей, всё в порядке?»
- Ачивки: «Первая сотня операций!», «Месяц без пропусков», «Сэкономил 10к за месяц»
- Совет дня/недели по финансовой грамотности (из заготовленного списка)

**Реализация**:
1. Новая таблица `budgets` (user_id, category, monthly_limit, currency)
2. Новая таблица `user_stats` (user_id, streak_days, total_operations, achievements_json)
3. Сервис `services/scheduler.py` — cron-подобная логика для дайджестов (через `APScheduler` или `python-telegram-bot` JobQueue)
4. Сервис `services/retention.py` — генерация дайджестов, проверка стриков, ачивки
5. Дайджесты генерируются через LLM (живой текст, не шаблон)
