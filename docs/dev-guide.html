🚀 Quickstart (локальная разработка)

🚨
НЕ используй продакшн токен бота для разработки! Создай отдельного тестового бота через @BotFather и пиши только к нему. Иначе сообщения реальных пользователей будут проходить через твой дев-инстанс.

1. Клонировать и поднять окружение

git clone https://github.com/Tue22869/Rich-Uncle-Scrooge.git
cd Rich-Uncle-Scrooge

# Создать виртуальное окружение
python -m venv venv
source venv/bin/activate   # Linux/macOS
# venv\Scripts\activate   # Windows

pip install -r requirements.txt

2. Заполнить .env

cp env.example .env
# Открой .env и вставь свои ключи (см. секцию Env vars)

3. Запустить

python main.py

База данных (smartfinances.db) создаётся автоматически при первом запуске. Миграции встроены в db/session.py — Alembic не используется.

Подтверждение действий (PendingAction)

Перед каждой операцией (доход, расход, перевод, удаление) бот создаёт запись PendingAction в БД со статусом PENDING и показывает инлайн-кнопки Подтвердить / Отмена. Только после нажатия «Подтвердить» (callback_handler) запись меняется на CONFIRMED и операция применяется. PendingAction протухает через несколько минут (expires_at).

Основные модели БД
  • User — tg_user_id, timezone, default_account_id, google_sheets_id
  • Account — название, валюта, баланс, is_default
  • Transaction — income / expense / transfer, сумма, дата, категория
  • PendingAction — очередь ожидающих подтверждения операций
Команды бота
  • /start — регистрация / приветствие
  • /accounts — список счетов и балансов
  • /report — финансовый отчёт за период
  • /sheets — привязка Google Sheets
  • /sheets_export — экспорт транзакций
  • /sheets_import — импорт из таблицы
  • /help — помощь
  • Любой текст / голос → LLM-парсер

🤖 LLM — каскадная система моделей

ℹ️
Зачем каскад? Быстрая и дешёвая модель (gpt-4o-mini) справляется с 90% запросов. На сложных или неоднозначных фразах она возвращает низкий confidence или validation error — тогда подключается более умная модель (gpt-4o). Так экономим деньги без потери качества.

Конфигурация моделей (llm/parser.py)

PRIMARY_MODEL  = "gpt-4o-mini"   # дешёвый, быстрый — первая попытка
FALLBACK_MODEL = "gpt-4o"        # умнее, дороже — если primary не справился
ANALYSIS_MODEL = "gpt-4o"        # для LLM-анализа отчётов и инсайтов

Два типа LLM-вызовов

1. parse_message() — парсинг команд
  • Режим: json_object
  • Temperature: 0 (детерминированный)
  • Системный промпт кешируется в памяти (_CACHED_SYSTEM_PROMPT)
  • В контекст передаются счета пользователя и дата/время
  • Ответ валидируется через Pydantic (LLMResponse)
2. generate_analysis() — аналитика
  • Режим: free-form текст
  • Temperature: 0.4 (чуть живее)
  • Модель: ANALYSIS_MODEL (gpt-4o)
  • Вызывается по кнопке «Анализ» в отчётах
  • На вход — структурированный текст отчёта/инсайта

⚠️
Меняешь промпт? Сбрось кеш! Системный промпт кешируется в _CACHED_SYSTEM_PROMPT. При изменении llm/prompts.py нужно перезапустить процесс — при локальной разработке это происходит само, в продакшне нужен docker restart.

🎙️ SpeechFlow — голосовые сообщения

🔴
Мы на бесплатном демо-плане SpeechFlow! Бесплатный план даёт 30 минут распознавания суммарно. После исчерпания голосовые сообщения перестанут работать до смены ключей или перехода на платный план.
Как работает
  1. Пользователь шлёт голосовое сообщение
  2. voice_message_handler скачивает .ogg во временный файл
  3. services/speech.py → transcribe_audio() загружает файл в SpeechFlow
  4. Поллинг результата каждые 2 сек, макс 30 попыток
  5. Полученный текст идёт в обычный parse_message()
Управление ключами
  1. Зайти на speechflow.io
  2. Dashboard → API Keys → Create new key
  3. Обновить SPEECHFLOW_KEY_ID и SPEECHFLOW_KEY_SECRET в .env на сервере
  4. Перезапустить контейнер: docker restart smartfinances_bot
⚠️
Для локальной разработки с голосом: создай свой демо-ключ на SpeechFlow и используй его в своём .env. Не используй прод-ключи — один разработчик может случайно израсходовать весь лимит.

Конфигурация в services/speech.py

SPEECHFLOW_KEY_ID     = os.getenv("SPEECHFLOW_KEY_ID", "")
SPEECHFLOW_KEY_SECRET = os.getenv("SPEECHFLOW_KEY_SECRET", "")

CREATE_URL = "https://api.speechflow.io/asr/file/v1/create"
QUERY_URL  = "https://api.speechflow.io/asr/file/v1/query"

# Поллинг: 30 попыток × 2 сек = до 60 сек ожидания
max_attempts  = 30
poll_interval = 2.0

🗄️ База данных

Используется SQLite через SQLAlchemy. На продакшне база лежит в Docker volume (./data/smartfinances.db), не в самом контейнере — данные переживают пересборку образа.

Миграции

ℹ️
Alembic не используется. Миграции — это ALTER TABLE ... ADD COLUMN вручную в функции _ensure_sqlite_schema() в db/session.py. При добавлении нового поля в модель — добавляй туда же проверку. 
# db/session.py — пример добавления колонки
def _ensure_sqlite_schema():
    with engine.connect() as conn:
        cols = conn.execute(text("PRAGMA table_info(users)")).fetchall()
        existing = {row[1] for row in cols}

        if "new_column" not in existing:
            conn.execute(text("ALTER TABLE users ADD COLUMN new_column VARCHAR"))
            conn.commit()

Резервное копирование прода

# Скопировать базу с сервера локально
scp root@31.130.131.71:/var/www/smartfinances/data/smartfinances.db ./backup.db

🚢 Deploy на прод

Прод живёт на сервере 31.130.131.71, код в /var/www/smartfinances, запускается через Docker Compose.

Стандартный деплой

# 1. Запуш изменения в main
git push origin main

# 2. Зайди на сервер
ssh root@31.130.131.71

# 3. Подтяни и пересобери
cd /var/www/smartfinances
git pull origin main
docker compose down && docker compose up -d --build
⚠️
docker restart ≠ docker compose up --build
docker restart перезапускает старый образ без нового кода. Для применения изменений в Python-файлах нужен --build. Исключение: если менялось только содержимое .env на сервере — достаточно docker compose down && docker compose up -d (без --build).

Полезные команды на сервере

# Логи в реальном времени
docker logs -f smartfinances_bot

# Статус контейнеров
docker ps

# Зайти внутрь контейнера
docker exec -it smartfinances_bot bash

# Проверить переменные окружения внутри контейнера
docker exec smartfinances_bot env | grep -E "TELEGRAM|OPENAI|SPEECHFLOW"

📊 Google Sheets — интеграция

ℹ️
Фича опциональная. Без GOOGLE_APPLICATION_CREDENTIALS бот работает полностью нормально. Google Sheets нужны только если пользователь хочет видеть/редактировать данные в таблице.

Концепция — как это устроено

У бота есть один сервисный аккаунт Google (Service Account) — это как «технический пользователь» в Google Cloud. Каждый пользователь бота создаёт свою собственную таблицу в Google Sheets и расшаривает её этому аккаунту как редактора. Бот ничего не хранит в облаке сам — он только читает и пишет в таблицу пользователя по запросу.

🚨
Синхронизация НЕ автоматическая!
/sheets_export и /sheets_import — это ручные операции. Типичный флоу: экспорт → редактируешь таблицу → импорт. /sheets_import полностью заменяет данные в боте данными из таблицы — без возможности отката!

Настройка для разработчика (один раз на деплой)

  1. Открыть Google Cloud Console → создать новый проект (или использовать существующий)
  2. APIs & Services → Enable APIs → найти и включить Google Sheets API
  3. IAM & Admin → Service Accounts → Create Service Account
    • Имя: например smartfinances-bot
    • Роли давать не нужно — доступ управляется через расшаривание таблицы
  4. В созданном сервисном аккаунте: Keys → Add Key → JSON → скачать файл
  5. Положить JSON-файл рядом с проектом, прописать путь в .env:
    GOOGLE_APPLICATION_CREDENTIALS=./google_credentials.json
  6. На продакшне — файл монтируется в Docker:
    ./google_credentials.json:/app/google_credentials.json:ro
⚠️
Email сервисного аккаунта — публичная информация.
Его нужно передавать пользователям, чтобы они расшарили таблицу. Бот показывает email автоматически при вызове /sheets. На проде используется аккаунт:
rich-uncle-scrooge-bot-648@rich-uncle-scrooge.iam.gserviceaccount.com

Пошаговый флоу для нового пользователя (инструкция внутри бота)

Что показывает /sheets если таблица ещё не привязана
  1. Создай пустую таблицу на sheets.google.com
  2. Нажми Share → добавь Editor для email сервисного аккаунта
  3. Скопируй ссылку на таблицу
  4. Пришли в бот: /sheets <ссылка>

Как работает импорт из таблицы

/sheets_import читает таблицу и полностью заменяет данные пользователя в боте:

  • Из вкладки Балансы — создаёт счета с указанными балансами
  • Из вкладок YYYY-MM — парсит транзакции (смотрит колонки Дата, Тип, Сумма, Валюта, Счет, Категория, Описание)
  • Строки с заголовками и итогами игнорируются
  • Тип транзакции определяется по значению в колонке «Тип»: доход / расход

Это значит, что в таблице можно редактировать данные (исправлять категории, описания, суммы) и потом «заливать» их обратно в бот через /sheets_import.

Как тестировать локально

# 1. Создай тестовый Google Sheet под своим аккаунтом
# 2. Либо используй существующий прод-ключ (попроси у тимлида)
#    либо создай свой сервисный аккаунт в Google Cloud (бесплатно)

# 3. В .env укажи путь к JSON-ключу

💣 Грабли и нюансы

🚨
Два бота на один токен = хаос
Если запустить локальный дев-инстанс с продакшн-токеном, он будет перехватывать сообщения реальных пользователей через long polling. Никогда так не делай. Создай отдельного бота для разработки.
⚠️
SpeechFlow: 30 минут — это мало
Демо-лимит общий на всю команду. Если голос перестал работать — скорее всего лимит исчерпан. Мониторить остаток можно в личном кабинете SpeechFlow. Заводи отдельный демо-аккаунт для разработки.
⚠️
concurrent_updates=False
Бот обрабатывает апдейты последовательно — это сознательное решение для SQLite. Не меняй это, пока база не будет заменена на PostgreSQL.
ℹ️
handlers.py — монолит ~2400 строк
Весь бот-логика живёт в одном файле. Прежде чем рефакторить — убедись что понимаешь flow PendingAction (подтверждения). Случайное дублирование хендлера или нарушение порядка регистрации в main.py ломает всё.
ℹ️
Telegram retry-логика
Message.reply_text и CallbackQuery.edit_message_text в handlers.py monkeypatched — добавлен авторетрай (4 попытки, exponential backoff) для TimedOut и NetworkError. Не удивляйся, если увидишь нестандартный стек.
⚠️
Промпт в llm/prompts.py — самый хрупкий файл
Любое изменение формата JSON-ответа в промпте должно синхронно отражаться в Pydantic-схеме schemas/llm_schema.py. Иначе Pydantic будет валить все запросы и бот будет отвечать «не понимаю».
